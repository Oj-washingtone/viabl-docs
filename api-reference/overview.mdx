Viabl renders beautiful, interactive API documentation directly from your OpenAPI specifications. Point to your spec file in `docs.json` or page frontmatter, and Viabl automatically renders endpoints, parameters, request and response schemas, code snippets, and interactive API runners.

---

## Generating Endpoint Pages

Update your `docs.json` to reference your OpenAPI specification. You can generate pages for all endpoints in your spec, or select specific endpoints.

### Generating all endpoint pages

To automatically generate pages for all endpoints in your OpenAPI specification, add an `openapi` property to any navigation group element:

```json
{
  "navigation": [
    {
      "group": "API reference",
      "openapi": "openapi.json"
    }
  ]
}
```

Viabl parses your spec, groups endpoints by tag, and automatically generates individual single endpoint pages for every route.

### Generating specific endpoint pages

To generate pages for only specific endpoints, list the target endpoints in the `pages` array of the navigation element:

```json
{
  "navigation": [
    {
      "group": "API reference",
      "openapi": "openapi.json",
      "pages": ["GET /users", "POST /users", "POST /gallery/upload"]
    }
  ]
}
```

Only the endpoints explicitly listed in the `pages` array will be rendered in the navigation tree.

## Hybrid MDX + OpenAPI Pages

You can write custom prose, prerequisites, diagrams, and warnings directly inside a physical `.mdx` file while attaching a specific OpenAPI endpoint to the page.

Set the `openapi` field in your page frontmatter to an HTTP method and path string:

```mdx
---
title: Upload Gallery Images
openapi: "POST /gallery/upload"
---

## Overview & Prerequisites

Before calling this endpoint, ensure you have obtained an **Album Token** from the developer dashboard.

> [!WARNING]
> Maximum upload size is **25 MB** per request. Supported image formats: `PNG`, `JPG`, `WEBP`.

### Upload Workflow

1. Provide the target `albumName` in the parameter form.
2. Drag and drop or choose your image files using the dropzone.
3. Click **Send Request** to execute the multi-part upload.
```

<Tip>
  Unlike full-spec pages, **Hybrid MDX Pages** render your custom markdown
  content directly in the documentation column above parameter tables and schema
  definitions.
</Tip>

## Filtering by Tag

For large specs, you can filter full-spec pages to only display endpoints matching a specific tag using the `openapiTag` frontmatter field:

```mdx
---
title: Users API
openapi: /openapi.json
openapiTag: Users
---
```

```mdx
---
title: Projects API
openapi: /openapi.json
openapiTag: Projects
---
```

Register them individually in your `docs.json` navigation:

```json
{
  "group": "API Reference",
  "pages": ["api-reference/users", "api-reference/projects"]
}
```

## Hidden Groups & Custom Layout Navigation

If you want single endpoint pages to remain live and routable without appearing in the left sidebar tree, set `"hidden": true` on any navigation group in `docs.json`:

```json
{
  "group": "Internal APIs",
  "openapi": "openapi.json",
  "hidden": true
}
```

Endpoints under a hidden group remain accessible via direct URL (e.g. `/api-reference/gallery-upload`). You can then create full-width overview pages without a sidebar using `sidebar: false`:

```mdx
---
title: API Directory
sidebar: false
---

# API Directory

Select an action below to explore its live endpoint runner:

- 🚀 [Upload Gallery Images](/api-reference/gallery-upload) — Upload single or multiple images.
- 📁 [List User Albums](/api-reference/gallery-albums) — Retrieve user albums.
```

## Multipart Form Data & Multi-File Uploads

Viabl automatically renders a sleek drag-and-drop dropzone UI for `multipart/form-data` endpoints.

It supports single binary files as well as array fields for uploading multiple files (`type: array` with items `format: binary`):

```yaml
paths:
  /gallery/upload:
    post:
      summary: Upload multiple gallery images
      requestBody:
        required: true
        content:
          multipart/form-data:
            schema:
              type: object
              properties:
                albumName:
                  type: string
                  example: "Summer Vacation 2026"
                images:
                  type: array
                  description: One or more image files to upload.
                  items:
                    type: string
                    format: binary
```

**Uploader Features:**

- Contextual badges indicating `(file)` vs `(multiple files)`.
- Real-time preview list with file names and size indicators.
- One-click **Clear files** button to reset selections.

## Exporting & Developer Tools

Viabl includes built-in developer tools across both API explorer and single endpoint views:

- **Postman Collection Export**: Download a ready-to-import Postman v2.1.0 collection file containing all endpoints, authentication headers, and request body schemas.
- **Quick Path Copy**: Click the copy button next to any endpoint path (`/gallery/upload`) to quickly copy it to your clipboard.
- **Dynamic Spec Versions**: Version pills automatically display the `info.version` value defined in your spec (e.g. `v1.0.0`).
- **Multi-Language Snippets**: Instant code snippet generation for cURL, JavaScript (Fetch/Axios), Python, Go, Java, PHP, and Ruby.

## Frontmatter Reference

<ResponseField name="openapi" type="string">
  Path to your OpenAPI spec file relative to project root (`/openapi.json`), or
  a method and path string (`"POST /gallery/upload"`) for hybrid endpoint pages.
</ResponseField>

<ResponseField name="openapiTag" type="string">
  Filter full spec pages to only show endpoints matching this tag (case
  sensitive).
</ResponseField>

<ResponseField name="sidebar" type="boolean">
  Set `sidebar: false` to hide the left navigation sidebar and enable full-width
  content layouts.
</ResponseField>

<ResponseField name="layout" type="string">
  Set layout mode: `"default"`, `"full"`, `"landing"`, or `"api"`.
</ResponseField>

## Example Spec Structure

A complete OpenAPI 3.0.3 spec demonstrating authentication, schemas, and multi-file upload endpoints:

```yaml
openapi: 3.0.3

info:
  title: Gallery & User API
  description: Complete API documentation for Viabl Gallery Services
  version: 2.1.0

servers:
  - url: https://api.example.com/v1
    description: Production

tags:
  - name: Users
    description: User management endpoints
  - name: Gallery
    description: Gallery and media upload endpoints

paths:
  /gallery/upload:
    post:
      tags: [Gallery]
      summary: Upload multiple gallery images
      requestBody:
        required: true
        content:
          multipart/form-data:
            schema:
              type: object
              properties:
                albumName:
                  type: string
                  example: "Summer Vacation 2026"
                images:
                  type: array
                  items:
                    type: string
                    format: binary
      responses:
        "200":
          description: Upload successful

  /users/{id}:
    get:
      tags: [Users]
      summary: Get a user profile
      parameters:
        - name: id
          in: path
          required: true
          schema:
            type: string
      responses:
        "200":
          description: User profile payload
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/User"

components:
  schemas:
    User:
      type: object
      properties:
        id:
          type: string
          example: usr_01abc123
        email:
          type: string
          format: email
          example: jane@example.com

  securitySchemes:
    bearerAuth:
      type: http
      scheme: bearer
      bearerFormat: JWT

security:
  - bearerAuth: []
```
